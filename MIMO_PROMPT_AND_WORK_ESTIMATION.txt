# TASK INSTRUCTION: Graft Previous Architecture into IIT KGP Administration & Employee Modules (With Super Admin & Full Feature Mapping)

## 1. Executive Summary & Core Rules
You must replace the current fragmented IIT KGP views by grafting the exact architecture, UI/UX, and workflows of the previous project (https://github.com/anirbanmid/ndli-club-management), augmented by the new architectural capabilities of this portal.

### The 3 Governance Tiers (Never Conflate):
1. SUPER ADMIN (super_admin_ops): Server infrastructure, deployment flags, runtime health, and local database backups.
2. CENTRAL ADMIN (central_admin): Business leadership at IIT Kharagpur (equivalent to "Admin" in admin.html). National analytics, club approvals, employee account management, succession desk, legacy data healing, and master CSV exports.
3. REGIONAL EMPLOYEE (regional_officer / EMP01-EMP07): Regional Zonal Officers (equivalent to employee.html). Daily member interactions, 1-row bulk calling, universal search, zonal grievance redressal, activity history, PI signature/affiliation management, and nodal CSV exports.

UI Standard: All login gates across all modules must replicate the exact clean, accessible UI/UX of the previous project. Zero internal engineering jargon (e.g. SLA_BREACHES, CHARTER_QUEUE_DEPTH) on any dashboard.

## 1. Executive Assessment
Is this a huge task?
NO. It is NOT a ground-up rewrite. It is a Medium-Sized, Highly Structured Refactoring & UI/UX Grafting Task.

## 2. Why It Is Manageable
1. Foundational Architecture Already Exists:
   - The core backend models (Club, CharterApplication, GrievanceTicket, ActivityLog, User, SubRole, etc.) are already implemented and validated by 622 passing unit tests.
   - Auth, session tokens, permissions, dual-layer challenge gates, and certificate issuance logic are fully working.
2. Proven Reference Design (Zero Guesswork):
   - The exact templates, color palettes, card designs, and JavaScript interaction patterns already exist in the previous project (ndli-club-management/templates/admin.html and employee.html).
   - This removes the time-consuming process of UI ideation, layout prototyping, and trial-and-error design.

## 3. Why MIMo Stumbled in the Previous Commit
MIMo did not fail due to excessive complexity; it failed due to a lack of architectural boundaries:
- It merged Central Admin and Employee forms into a single crowded view.
- It used a naive loop creating N database rows for a single bulk call instead of recording a single consolidated entry with a count.
- It exposed raw database column names (CHARTER_QUEUE_DEPTH, SLA_BREACHES) instead of calculating real human-readable operational business metrics.
